AGREED ARCHITECTURE (final state to build)
----------------------------------------
error/
  appError.js              <- base class (extends Error)
  badRequestError.js       <- 400
  unauthenticatedError.js  <- 401 (no/invalid token)
  unauthorizedError.js     <- 403 (valid token, not allowed)
  notFoundError.js         <- 404 (resource/route missing)
  conflictError.js         <- 409 (duplicate email etc.)
  internalServerError.js   <- 500 (unexpected crashes)

middleware/
  errorMiddleware.js       <- exports notFound + errorHandler
  authMiddleware.js        <- refactor later to throw

Naming convention: Class = PascalCase XxxError, file = camelCase xxxError.js

CLASS/STATUS MAPPING
--------------------
| Class                | File                    | Status | When                          |
|----------------------|-------------------------|--------|-------------------------------|
| BadRequestError      | badRequestError.js      | 400    | missing/invalid fields        |
| UnauthenticatedError | unauthenticatedError.js | 401    | no/expired/invalid token      |
| UnauthorizedError    | unauthorizedError.js    | 403    | valid token but no permission |
| NotFoundError        | notFoundError.js        | 404    | user/route/resource missing   |
| ConflictError        | conflictError.js        | 409    | "User already exists"         |
| InternalServerError  | internalServerError.js  | 500    | unexpected crashes            |

IMPORTANT DISTINCTION:
- 401 UNAUTHENTICATED = no token / bad token (authMiddleware)
- 403 UNAUTHORIZED   = logged in but forbidden (role checks)

BASE CLASS DESIGN (agreed)
----------------------------------------
export class AppError extends Error {
  constructor(message, statusCode) {
    super(message);                          // sets this.message
    this.statusCode = statusCode;            // HTTP status, read by middleware
    this.status = `${statusCode}`.startsWith("4") ? "fail" : "error";
    this.isOperational = true;  // label only, NOT a control-flow switch.
                                // middleware reads it: true = send real
                                // message; false = log stack, generic 500.
    Error.captureStackTrace(this, this.constructor);
    // captures call path at throw point, trims constructor frames so the
    // stack starts at where the error was thrown.
    // this.constructor resolves to the ACTUAL subclass thrown.
  }
}

Subclass example (pattern to follow):
  export class ConflictError extends AppError {
    constructor(message = "Conflict") {
      super(message, 409);
    }
  }

ERROR MIDDLEWARE DESIGN (agreed)
----------------------------------------
middleware/errorMiddleware.js exports TWO functions:

1. notFound (3 args: req, res, next)
   - catches any route that falls through
   - next(new NotFoundError(`Route ${req.originalUrl} not found`))

2. errorHandler (4 args: err, req, res, next) - MUST have 4 params
   - if err instanceof AppError -> respond with err.statusCode + err.message
   - else -> unexpected error: console.error(err.stack), respond generic 500
   - ALSO normalize DB/Mongoose errors here:
     * CastError (invalid ObjectId) -> 400
     * duplicate key (err.code === 11000) -> 409
     * Mongoose ValidationError -> 400

GOLDEN RULE: error middleware must be registered in server.js AFTER all
routes are registered (it is the last app.use).

KEY PRINCIPLES AGREED THIS SESSION
----------------------------------------
1. THROW, don't return status objects. Middleware only sees errors that
   are thrown. Current authService return-object pattern must die.
2. No try/catch needed in controllers/services thanks to Express 5 auto
   forwarding - EXCEPT for catch-and-transform (e.g. catch Mongoose
   duplicate key -> rethrow new ConflictError).
3. authMiddleware should throw UnauthenticatedError instead of
   res.status(401).json(...).
4. Error middleware is the single catch point for everything.
